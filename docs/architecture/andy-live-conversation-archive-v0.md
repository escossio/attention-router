# Andy Live Conversation Archive V0

> This V0 document describes the original text/voice archive. See [Live Conversation Artifact Links V1](andy-live-conversation-artifact-links-v1.md) for the separate image/document/video association candidate. It does not authorize any historical imports.

Status: isolated implementation candidate, disabled by default. Source of truth: existing Attention Router PostgreSQL. No new database, table, graph engine, APK interface or LLM service.

## Goal

After the owner activates observation for an explicit tenant and start instant, keep receiving newly observed WhatsApp text and voice evidence and organize it **by conversation and participant**.

A conversation is a bounded decision context, not a new personality, identity or independent assistant. People, relationships and the Cognitive Graph can be derived later; V0 archives evidence only.

## Reuse, no schema migration

- inbound_events: durable signed-ingress source, independent of language model or reply action
- conversation_threads: one per tenant, source, source account and conversation key
- conversation_participants and memory_actors: participants with available, source-backed identity; ambiguous voice/fromMe remains unattributed
- conversation_messages: provider message ID, direction, thread, author if grounded, original event timestamp, text if provided, source-event link and transcript status
- voice_transcriptions: existing trusted STT output joined by original inbound event ID

Existing archive code redacts recognized secrets and deduplicates messages. No MemoryIngestionJob or semantic MemoryClaim is generated by capture. No model is called solely for capturing or linking evidence.

## Live continuity

Existing signed WhatsApp ingestion continues. Only ORGANIC, wwebjs, whatsapp, message events with a READY conversation and provider ID are eligible. Types: chat, text, ptt or audio.

EXTERNAL_INBOUND is the incoming speaker. OWNER_MANUAL_OUTBOUND_OBSERVED is manually sent, mapped to the represented owner only if owner resolution is available; otherwise the sender remains unresolved. ROUTER_AUTOMATED_OUTBOUND_OBSERVED is machine-origin; UNKNOWN_FROM_ME is explicitly unattributed. Neither is silently turned into an owner command or granted authority.

Two times: sent_at (provider occurrence time when valid, otherwise receipt time) and metadata.source_received_at (ingress receipt time). Audio is archived with no text and pending transcription; trusted STT later enriches the same message, preserving identity, conversation and timestamp. Failed STT retains the message with failure status.

If a trusted manual outbound message comes without text, keep TEXT_UNAVAILABLE. The Transport normally suppresses manual-owner direct-chat text. A separate explicit operator flag can allow text from a fully classified manual owner direct-chat event; unknown, automated, unresolved and nontext input remains masked by default.

A bounded Worker reconciliation pass (up to 25 eligible missing receipts and 25 already archived but not yet enriched voice messages about once a minute) recovers errors after the fixed capture watermark from existing durable ingress events, including completed STT when available. Both queries are bounded independently to avoid STT repair starvation. It does not replay decisions, execute actions, send responses or scan old conversations. Duplicate scope disagreements fail closed.

## Historical acceleration

Intentionally deferred by owner decision. No historical imports, backfill, old audio retrieval, Android file scanning, retrospective bootstrap or old-cursor rewind. CONVERSATION_CAPTURE_START_AT must be UTC offset-aware whenever capture is enabled; restarting with the same fixed watermark does not import earlier history. Existing historical bootstrap remains unchanged.

## Configuration and rollout

- API and Worker: CONVERSATION_CAPTURE_ENABLED=false by default
- API and Worker: CONVERSATION_CAPTURE_START_AT mandatory, a fixed new UTC instant
- API and Worker: optional private CONVERSATION_CAPTURE_TENANT_ID for an exact tenant
- Transport: CONVERSATION_CAPTURE_OWNER_TEXT_ENABLED=false by default; requires configured tenant and forwarding
- Transport: CONVERSATION_CAPTURE_OWNER_VOICE_ENABLED=false by default; requires configured tenant and forwarding, a verified manual owner origin, ready direct conversation and audio media
- The current Transport's unattributed UNKNOWN_FROM_ME voice observations are retained as evidence, but not downloaded or attributed to the owner by this opt-in. This can leave some outgoing PTT audio without transcriptions. No biometric identification is involved.
- Existing memory extraction, conversation response, agent, outbox, group presence and STT authorization flags remain independent

Before enabling in production, certify the exact GitHub SHA, test source/tenant/speaker safety, and preserve API, Worker and Transport image IDs for rollback. Start only with the owner-authorized tenant and a fresh watermark. Disabling the flag stops new collection; it does not delete already archived evidence.

## Trust, privacy and network placement

The existing Transport -> signed internal ingress -> application -> PostgreSQL path is reused; the Worker updates the same PostgreSQL when STT completes. No new connection, port, VLAN, static IP, L2/L3 identity, credential, container or authority is introduced. Provider text is untrusted data, not a control instruction. Keep chat IDs, real messages and private environment values out of the repository and logs. Limit archive access and validate retention and backups before broad deployment.

## Acceptance

Synthetic tests cover new text received and sent in the same conversation, timestamp/provenance, missing text, unattributed fromMe, source replay deduplication, ready/failed STT on the original message, cross-tenant denial, historical cutoff, retry after missing archive, no generated reply and no memory extraction. The Transport gate preserves default masking and group behavior.

No voice biometrics, whole-chat-model prompts or complete WhatsApp media coverage are claimed.
