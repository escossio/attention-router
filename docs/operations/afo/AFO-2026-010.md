# AFO-2026-010 — Identidade de desenvolvimento “Alex” vaza para resposta real

**Status:** ROOT_CAUSE_PROVEN / PARKED  
**Classe:** identidade / contexto operacional

### Incidente real

Mensagem recebida em 2026-09-20 11:29 local:

`Leonardo. Bom dia! Eu não sei o que você pretende novamente com a troca de números.`

Resposta gerada e efetivamente enviada:

`Bom dia, Leonardo. Sou o assistente virtual do Alex. Você quer deixar essa mensagem para ele ou pedir que ele entre em contato?`

Persistência:

- `semantic_source=OPENAI_AGENTS_SDK`
- `response_source=OPENAI_AGENTS_SDK`
- ExecutionIntent `SENT`
- Outbox `DONE`

### Origem comprovada de “Leonardo”

Veio da mensagem recebida. Não foi inventado pelo sistema.

### Origem comprovada de “Alex”

A `main` contém literalmente nas instruções do agente:

`Você é Andy, assistente virtual do Alex.`

O mesmo placeholder aparece também em:

- `config/andy_behavior_profile.json`;
- seed do tenant padrão em `repository.py`;
- registry/fixtures/testes históricos.

Para o incidente específico, a resposta veio do OpenAI Agents SDK, portanto as instruções do agente são causa direta suficiente para o nome “Alex”.

### Falha arquitetural

Identidade humana operacional pode nascer de literal/fixture de desenvolvimento em vez de uma entidade canônica autenticada e fornecida pelo Router.

### Estado

Parked. Não substituir “Alex” por outro hardcode. A correção futura deve remover identidade pessoal do prompt estático.

### Critério de fechamento

Nenhum nome pessoal em prompt operacional estático; owner/represented subject deriva exclusivamente de identidade canônica comprovada. Ausência de identidade deve falhar de forma segura e neutra.
