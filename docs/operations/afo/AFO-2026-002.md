# AFO-2026-002 — Falha de detecção do pipeline degradado

**Status:** ROOT_CAUSE_PROVEN  
**Classe:** observabilidade operacional

### Sintoma

A Engine deixou de responder e o ponto de falha não ficou imediatamente evidente. A investigação exigiu inspeção manual de banco, containers e fluxo.

### Causa raiz

O runtime possuía sinais locais de saúde, mas não havia uma visão E2E suficientemente explícita para diferenciar:

- mensagem recebida;
- Grace aguardando legitimamente;
- Worker ausente;
- Queue não consumida;
- Decision legítima em DRY_RUN;
- ExecutionIntent bloqueada;
- Outbox inexistente versus pendente.

### Impacto

A falha levou dias para ser localizada com precisão e motivou a criação do painel, segmentação e OpenTelemetry.

### Observabilidade obrigatória para fechamento

O painel deve distinguir `NOT_CREATED`, `WAITING`, `BLOCKED`, `DONE`, `FAILED` e `NOT_APPLICABLE` em cada estágio.

Todo trace deve expor, de forma segura:

- correlation_id;
- estágio atual;
- razão terminal/bloqueio;
- idade no estágio;
- componente responsável;
- runtime image/build SHA;
- config fingerprint;
- trace/span IDs quando disponíveis.

### Critério de fechamento

Uma falha sintética de cada classe deve ser diagnosticável pelo painel/logs sem shell no host.
