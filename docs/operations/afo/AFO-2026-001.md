# AFO-2026-001 — Generic Worker não retorna após reboot

**Status:** ROOT_CAUSE_PROVEN  
**Classe:** continuidade de runtime / supervisão

### Sintoma

A Andy recebia mensagens, mas o pipeline deixava de avançar pelos estágios dependentes do Generic Worker.

### Último estado bom conhecido

Worker `idiolect-v1l-6611eac1`, criado em 2026-09-20, respondendo ponta a ponta.

### Evidência principal

Backup de `docker inspect` do Worker:

- `StartedAt=2026-09-20T04:05:32Z`
- `FinishedAt=2026-09-22T00:45:57Z` (21/09 21:45:57 local)
- `ExitCode=137`
- `OOMKilled=false`
- `RestartPolicy.Name=no`

Histórico do host:

- shutdown em 21/09 21:45;
- boot em 21/09 21:46.

### Causa raiz

Um componente necessário para o fluxo operacional estava sem política de restart/supervisão. O shutdown encerrou o Worker e o boot não o restaurou.

### Fatores contribuintes

- ausência de supervisor dedicado;
- ausência de invariant/health gate que declarasse o pipeline indisponível sem Worker;
- ausência de alarme de “zero consumidores” para Grace/Queue.

### Impacto

Mensagens continuaram chegando, mas etapas dependentes do Worker deixaram de ser consumidas.

### Correção aplicada até agora

O Worker atual está com `restart=unless-stopped`, mas isso ainda não fecha a AFO: falta provar cold boot e formalizar o contrato de supervisão.

### Observabilidade obrigatória para fechamento

- estado do Worker como componente obrigatório do pipeline;
- contador de consumidores vivos;
- heartbeat do Worker;
- idade máxima de Grace aberta;
- idade máxima de Queue PENDING;
- alarme quando ingress está ativo e worker_count=0.

### Teste de regressão necessário

Cold reboot controlado do host com prova de que o Worker retorna automaticamente, torna-se healthy e consome um canário sem intervenção manual.

### Critério de fechamento

Reboot + E2E físico PASS e alerta de ausência de Worker validado.
