# AFO-2026-012 — Proxy Grafana perde upgrade Live e encaminha Basic Auth externo

**Status:** VERIFIED — falhas de proxy corrigidas; causalidade do DOM não provada.
**Classe:** observabilidade / reverse proxy / autenticação
**Data:** 2026-09-26 UTC (2026-09-25 no fuso do operador).

## Escopo e governança

Causa comprovada antes de reservar o ID. O índice e o AFO-011 foram reconciliados
primeiro: 011 é DISCARDED, não é incidente válido e seu ID permanece reservado.

- Apache 2.4.68; proxy_http, proxy_wstunnel e headers já carregados.
- Grafana 13.2.2 healthy, database=ok; Zabbix plugin 6.8.0.

## Configuração anterior e reprodução

O vhost exigia Basic Auth e encaminhava toda a árvore por HTTP genérico:

```apache
<Location />
    AuthType Basic
    AuthName "ROC-E2E Grafana"
    AuthUserFile /path/to/existing.htpasswd
    Require valid-user
</Location>
ProxyPass / http://127.0.0.1:18083/ retry=0 timeout=60
ProxyPassReverse / http://127.0.0.1:18083/
```

Credenciais existentes foram validadas sem impressão. Uma sessão Grafana válida
foi mantida somente em memória. O mesmo handshake RFC 6455, com Origin correto,
produziu 101 no backend, 400 no Apache e 400 na URL pública.

A sequência autenticada pelo proxy acionou auth.client.basic e password-auth.failed
no Grafana (cinco registros de falha na janela curta, quatro erros do cliente Basic).
Uma fixture isolada com Apache real e credenciais sintéticas comprovou que o
backend recebe Authorization e perde Upgrade com a configuração anterior.
Nenhuma credencial real foi capturada em tráfego ou persistida em evidência.

## Causas comprovadas

1. A rota HTTP genérica não está configurada para preservar/tunelar o upgrade
   WebSocket. Não basta o módulo estar carregado: nesta configuração o handshake
   válido chega ao upstream sem Upgrade e é recusado.
2. Authorization do Basic Auth externo atravessa o proxy. Grafana o interpreta
   como sua própria autenticação Basic, produzindo tentativas inválidas e bloqueio.
   Isso independe do funcionamento dos datasources e da existência de cookie válido.

## Correção mínima aplicada

Fonte: `ops/provisioning/grafana-apache/`, branch
`fix/grafana-apache-live-auth`, originada da main acima.
Commit: `11745344d75708474c13a6d40e0b5389a143a03b`.

```apache
# Dentro do Location autenticado, sem a opção early:
RequestHeader unset Authorization

# Antes do ProxyPass genérico:
ProxyPass /api/live/ws ws://127.0.0.1:18083/api/live/ws
ProxyPassReverse /api/live/ws ws://127.0.0.1:18083/api/live/ws
```

A remoção ocorre na fase fixup, depois da autenticação Apache. O Grafana continua
exigindo sua própria sessão; não foi habilitado acesso anônimo. O vhost live foi
renderizado dessa fonte, comparado com o candidato e instalado com backup.
`apache2ctl configtest`: Syntax OK; aplicado somente `systemctl reload apache2`.
O PID principal do Apache não mudou. Nenhum container foi reiniciado.

## E2E de navegador e limite causal

Antes: Chrome limpo, URL exata, 60 segundos e refresh 10s: seis consultas de
painéis HTTP 200, nove erros WebSocket, zero page errors e nenhum insertBefore.
Depois: Chrome 153.0.8010.52 limpo, URL exata, cinco minutos e refresh 10s:
30 consultas HTTP 200, Live 101, zero erros WebSocket, zero erros de console,
zero page errors e nenhum insertBefore. Dashboard PASS nessa janela.

No intervalo pós-reload: zero Live HTTP 400, zero password-auth.failed e zero
erros auth.client.basic. API health pública 200/database=ok; datasource Zabbix
e Tempo pela URL pública 200/status OK. Tempo /ready e recuperação de trace
retornaram 200; o contador de spans cresceu de 2803 para 3145 (+342).
A prova externa usa HTTP client e Chrome; um probe Python urllib recebeu 403
na borda, sem alcançar o Apache. Isso não foi tratado como falha do Grafana
em face dos probes autenticados e do navegador funcionando.

Não reproduzir o DOM exception não prova que o proxy o causava. Se reaparecer,
isolar painel/componente (incluindo Canvas), plugin, tradução/extensões e versão
do navegador com console/stack. Não aplicar alterações aleatórias ao dashboard.

## Rollback

Restaurar o backup privado do vhost no destino real do symlink habilitado,
executar `apache2ctl configtest` e, somente com Syntax OK, recarregar Apache.
Não alterar .htpasswd, Grafana, datasource ou container. O renderer preserva a
paridade entre fonte Git e runtime. O rollback reapresenta os defeitos conhecidos.

A fixture executa os estados anterior e corrigido e comprova a reversibilidade
funcional. Não houve rollback de produção para reintroduzir o incidente.
